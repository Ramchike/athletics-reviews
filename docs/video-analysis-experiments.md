# Удалённые кадры и пробный анализ суставов

Проверено 4 октября 2026 года на выбранных фрагментах шести личных записей из Google Диска и демонстрациях Лайлса. [Результат 14 подходов](../reviews/athlete-a/2026-10-04-video-methods.md) относится к пользователю в красном. Это экспериментальные инструменты; независимой проверки точности суставов или оценки техники пока нет.

## Чтение без сохранения целого видео

`scripts/stream_frames.py` открывает удалённый файл через PyAV и читает ограниченные HTTP Range. Сервер должен вернуть 206 и точный `Content-Range`; полный ответ 200 отклоняется до чтения тела. В памяти кэшируется до восьми блоков по 1 МиБ. На диск сохраняются выбранные кадры и manifest, а не оригинал.

Для доступного публичного файла Google Диска использовался адрес `https://drive.usercontent.google.com/download?id=<ID>&export=download&confirm=t`. Это проверенный адрес для данных файлов, не универсальный обход авторизации. Если сервер перестал отдавать диапазоны или файл недоступен, программа сообщает ошибку. Не записывайте подписанные ссылки или токены доступа в Git.

```bash
python scripts/stream_frames.py \
  --url 'https://drive.usercontent.google.com/download?id=<ID>&export=download&confirm=t' \
  --at 193.4 194.4 195.13333333333333 \
  --out media/new-review/selected --lossless
```

Результат создаётся только в новой папке внутри `media/`; существующее содержимое не перезаписывается. По умолчанию кадры JPEG, с `--lossless` — PNG. Для ключевого измерительного кадра используйте PNG и проверьте отсутствие уменьшения исходного разрешения. Программа ограничивает максимальную сторону 1280 пикселями; при большем исходнике для точных кадров нужно явно передать больший `max_side` в Python-функцию `extract`.

Manifest содержит запрошенное время, фактический PTS декодированного кадра, его SHA-256, размер исходника и число прочитанных сетевых байтов. SHA-256 всего удалённого видео остаётся неизвестным. Метка времени файла не восстанавливает исходную скорость замедленного движения. JPEG-копия для просмотра отличается от исходных декодированных пикселей; PNG нужен для сохранения этих пикселей.

Повторные seek и выбор кадров далеко друг от друга могут читать много сетевых байтов. В этой работе вместе с поиском пользователя, повторными выборками и эталонами прочитано примерно 600 МБ по сети. Одна расширенная поисковая выборка IMG_8466 завершилась сетевым таймаутом после 28 кадров; основной обзор и личный короткий фрагмент завершены. Частичный поиск не выдаётся за полный просмотр.

## Скелет и принадлежность человеку

Нужен отдельный Python 3.12 с [requirements-video-analysis.txt](../requirements-video-analysis.txt). На Linux также могут понадобиться `libEGL.so.1` и `libGL.so.1`. Для этого компьютера библиотеки распакованы локально в `/home/ramchike/.cache/athletics-video-libs/extracted/usr/lib/x86_64-linux-gnu`; системная установка не менялась. Этот путь — состояние данного компьютера, а не переносимая настройка проекта.

Официальные модели [MediaPipe](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker#models) `.task` хранить в `media/`. Для основного личного эксперимента использованы Lite и Full с MediaPipe 0.10.32, CPU, режим IMAGE. Ранняя версия среды 1.0.1 дала сбой чтения масок; результаты основной личной проверки получены после перехода на 0.10.32. IMAGE обрабатывает кадры независимо; это не непрерывный трекер анатомической стороны.

```bash
python scripts/pose_probe.py media/new-review/selected \
  --model media/models/full.task --crop-y 360 --red-shirt --red-identity \
  --suffix checked
```

`--red-shirt` — вспомогательный поиск красной одежды на переднем плане именно для этих записей, не универсальная идентификация спортсмена. `--red-identity` проверяет положение плеч и цвет нескольких участков торса. При перекрытии модель может потерять человека: неизвестные точки не становятся достоверными от увеличения числа нарисованных линий.

Для другой одежды используйте явно выбранную область и ручную проверку. Вариант `--centers X_START X_END` задаёт линейное движение центра области по извлечённым кадрам. `--rotate 90` исправлял ориентацию IMG_8472 только в производном изображении.

Скрипт сохраняет координаты в пикселях кадра, видимость, предполагаемые world-координаты, маски и линии. Формат изображения учитывается до вычисления углов; нормализованные `x` и `y` нельзя напрямую подставлять в евклидов угол широкого кадра. Для PNG-источников отдельные изображения с линиями сохраняются в PNG, остальные пиксели кадра не дорисовываются.

## Сравнение

`scripts/analyze_pose_experiments.py` воспроизводит основной эксперимент из сохранённых наборов и создаёт диагностические изображения. Для текущих данных:

```bash
python scripts/analyze_pose_experiments.py \
  --root media/review-2026-10-04 \
  --student red-8466-active --reference reference-A \
  --out-name another-experiment \
  --sensitivity-source red-8466-active \
  --sensitivity-suffixes whole-v4 crop-v4 lite-v4 red-located-v4 \
  --no-mirror-reference
```

Это исследовательский сценарий с именами наборов текущей работы. Он не принимает произвольные два ролика и не создаёт автоматически спортивный вердикт. Для нового занятия сначала извлечь и проверить кадры, затем выбрать совместимые наборы и описать ограничения.

После замечания пользователя перестановка левых и правых меток полностью убрана. Раньше сравнивались разные ноги; зависимые числа отозваны. Кандидатные пики могут выбираться только для той же стороны модели, а анатомию всё равно нужно проверить вручную. Отражение изображения выключено по умолчанию в эксперименте и отсутствует в ручном просмотрщике. Procrustes может подавить разницу наклона; DTW может скрыть различия ритма. Изменение дистанции алгоритма не является улучшением спортсмена.

`scripts/build_video_review.py` создаёт отдельный автономный UTF-8 HTML для каждого участника. Он сохраняет все извлечённые кадры выбранного фрагмента, включая нераспознанные. Есть два отдельных ползунка, кнопки соседних кадров, необязательные суставы модели (выключены по умолчанию) и ручные наблюдения. Графики старого сравнения и численные баллы в страницы не включаются.

```bash
python scripts/build_video_review.py --root media/review-2026-10-04 --person red --config reviews/athlete-a/2026-10-04-manual-pages.json
python scripts/build_video_review.py --root media/review-2026-10-04 --person white --config reviews/athlete-a/2026-10-04-manual-pages.json
```

Контроль `same_side_peak` проверяет, что более похожий пик противоположной ноги не выбирается и что отсутствие той же стороны вызывает явную ошибку. Подписанное повторение B-/C-skip пользователя пока не подтверждено, поэтому наличие эталонов B и C в просмотрщике не означает завершённого личного сравнения этих упражнений.

## Проверки и хранение

Четыре новых проверки: ограниченный диапазон чтения и seek через границы блоков; отказ от полного HTTP-ответа; угол независимо от начала координат; DTW при повторении той же фазы. Вместе с семью существующими проверками библиотеки выполнены **11 тестов, успешно**. Проверки приёма используют искусственные видео; обычный сценарий теперь имеет фиксированную тестовую ёмкость диска, отдельный сценарий по-прежнему проверяет отказ при недостатке места.

Для полной проверки нужны `ffmpeg` и `ffprobe` в PATH; для новых проверок — отдельная среда анализа. При отсутствии её зависимостей новые тесты пропускаются, стандартные инструменты библиотеки не получают обязательной ML-зависимости.

```bash
python -m unittest discover -s tests -v
```

На этом компьютере исполняемые файлы для проверки находятся в `/home/ramchike/.cache/athletics-video-tools`. Просмотрщик проверен в браузере: загрузка кадров и графиков, смена времени и эталона, отключение линий и изменение порога. Это проверка работы инструментов, не валидация биомеханики.

Медиа, модели, графики и HTML остаются в игнорируемой папке `media/`. В Git идут код, требования среды и текстовый разбор. Удалённые источники учтены отдельно в `reviews/athlete-a/2026-10-04-video-sources.json`: местный приёмщик `video_library.py` не запускался, поскольку он требует копию оригинала и полную контрольную сумму. Его карточки не подменяются фиктивным импортом.

Сохранённые кадры и инструменты занимают место отдельно от HTML; один HTML около 11 МБ. Полные личные MOV не сохранены. Сеть, доступ к Диску и расположение оригиналов нужны для повторного извлечения кадров; обещания постоянной доступности ссылки нет.
