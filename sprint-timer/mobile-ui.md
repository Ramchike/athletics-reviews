# Створ · мобильный интерфейс

Система светлых компонентов для веб-пилота. Из shadcn/ui взяты структура Input (постоянная подпись, фокус и ошибка) и Item (строка единого действия). Компоненты реализованы на нативных HTML-контролах, чтобы сохранить поведение клавиатуры и селекторов браузера. Визуальные примеры из других приложений служат ориентиром для структуры.

- [shadcn/ui Input](https://ui.shadcn.com/docs/components/input) и [Item](https://ui.shadcn.com/docs/components/item)
- [Fi на Mobbin](https://mobbin.com/screens/7ef9db93-b1d2-400a-8cd0-2850a7dcbb57) использует два сегмента над меняющимся содержимым.
- [Claude на Mobbin](https://mobbin.com/screens/7521c8ef-05f3-410d-91c1-3252e319f6a8) показывает строку с индикатором перехода и отдельное действие добавления. В Створе добавление в правом верхнем углу списка.

## Сущности

| Сущность | Что видно |
| --- | --- |
| Телефон | Старт создаёт комнату. Финиш сканирует QR или вводит код. |
| Комната | Код и QR, готовность второго телефона, активная попытка. |
| Спортсмен | Имя, отдельный экран истории. |
| Попытка | Дистанция, время, дата и спортсмен, если он выбран. |

## Пользовательские истории

- Хочу запустить отсчёт со стартового телефона. Выбираю «Старт» и одно основное действие.
- Хочу присоединить камеру второго телефона. Выбираю «Финиш» и вхожу по QR или коду.
- Хочу быстро добавить спортсмена. Открываю «Спортсмены», нажимаю «+» и ввожу имя.
- Хочу увидеть предыдущие попытки одного спортсмена. Нажимаю его строку и открываю экран результатов. «‹ Спортсмены» возвращает в тот же список.

## Путь пользователя

| Шаг | Действие | Ответ интерфейса |
| --- | --- | --- |
| Выбор роли | «Старт» или «Финиш» | Показывается панель выбранной роли. Приглашение с кодом сразу открывает «Финиш». |
| Сопряжение | Создать комнату, отсканировать QR или ввести код | На старте виден QR. На финише ошибка кода показывается у поля. |
| Забег | Выставить камеру, подтвердить готовность, запустить отсчёт | Оба телефона показывают завершённый замер. |
| История | «Спортсмены» → строка имени | Экран имени показывает только его результаты. |
| Добавление | «+» → имя → «Добавить» | Открывается экран нового спортсмена. Повтор имени оставляет форму открытой и показывает ошибку. |

## Проверка применимых Apple HIG

| Раздел | Решение |
| --- | --- |
| [Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls) | Два коротких взаимоисключающих варианта. Оба видны, подписи помещаются целиком. |
| [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) | Снизу только корневые разделы. Действия «Создать» и «Добавить» находятся в содержимом экранов. |
| [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables) | Вся строка ведёт в детали. Индикатор перехода справа. В деталях видны только связанные попытки. |
| [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars) и [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) | «+» справа в заголовке списка с доступным именем. Основное действие выделено заливкой. Нажатие меняет масштаб и яркость. |
| [Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields) | Подпись сохраняется, поле имеет высоту от 44 CSS px и шрифт 16 px. Ошибка связана с полем. Имя вводится обычной клавиатурой, код поддерживает буквы и цифры. |
| [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets) | Один короткий диалог для добавления, явная отмена. Жест закрытия смахиванием опущен, поскольку форма работает в браузере. |
| [Typography](https://developer.apple.com/design/human-interface-guidelines/typography) | Системный шрифт, умеренные заголовки, системное масштабирование текста. |
| [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) | Тап-зоны 44 CSS px в основных сценариях, видимый фокус и подписи. Снижение движения учитывается через prefers-reduced-motion. Подтверждение на физическом iPhone остаётся отдельной проверкой. |
| [Apple Design Resources](https://developer.apple.com/design/resources/) | Нативные компоненты используются как ориентир. UIKit и декоративные эффекты материала не нужны для текущего веб-пилота. |
