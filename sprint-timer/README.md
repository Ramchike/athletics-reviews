# Створ · таймер спринта 60/100 м

Прототип для двух телефонов и одного бегуна. На старте браузер заранее планирует последовательность сигналов. На финише MediaPipe Pose Landmarker Lite обрабатывает кадры на телефоне и интерполирует пересечение линии передней границей туловища. Сервер получает только состояние комнаты и метки событий. Финишный телефон сохраняет видео и кадры с линии в своём браузере. На старте запись включается отдельно, а в режиме «С ходу» используется камера старта. Каждый браузер хранит до 24 записей, до 45 секунд каждая. Видео можно открыть из истории на телефоне, который его снял. История результатов сохраняется в обоих браузерах, выгружается в CSV.

## Публичный пилот

Открой [stvor.theinventive.tech](https://stvor.theinventive.tech/) в Safari на каждом iPhone. Выпуск идёт из ветки `stvor-pilot` через Dokploy Compose на ru1. Контейнер проверяет `/readyz`, а HTTPS и WSS обслуживает Traefik.

## Локальный запуск

Из корня проекта:

```bash
npm --prefix sprint-timer ci
npm --prefix sprint-timer run setup
npm --prefix sprint-timer start
```

На компьютере открой http://localhost:4173. Для двух телефонов нужен общий HTTPS-адрес с действительным для них сертификатом. За существующим HTTPS-прокси используй `HOST=0.0.0.0`, `PORT=4173`, `PUBLIC_ORIGIN=https://<адрес>` и проксируй WebSocket на `/ws`. Сам сервер может принимать HTTPS с `TLS_CERT_FILE` и `TLS_KEY_FILE`, если оба телефона уже доверяют этому сертификату. Для пилота требуется один процесс. Комнаты живут в памяти и после рестарта создаются заново.

`setup` скачивает модель фиксированной версии и сверяет SHA-256. Для установленной модели команда использует локальный файл. `GET /healthz` подтверждает, что процесс отвечает. `GET /readyz` проверяет наличие клиентского кода, модели и WASM.

## На дорожке

1. Нажми «Создать старт». На втором телефоне нажми «Подключить финиш» и отсканируй QR со стартового телефона или введи код. Можно открыть и ссылку-приглашение.
2. Поставь финишный iPhone на продолжении ближнего края черты, ориентировочно в двух метрах от бегуна и с камерой на высоте между бедром и грудью. Сними сбоку так, чтобы бегун целиком помещался в кадре до и после линии. Выровняй линию, выбери направление и нажми «Проверить проход».
3. Нажми «Финиш готов». На старте выбери 60 или 100 м, режим сигнала и паузу 5–20 секунд, чтобы успеть занять позицию. Используй встроенный динамик, оставь оба Safari на переднем плане.
4. После забега открой запись и проверь два кадра на финишном телефоне. На стартовом телефоне появится то же время. «Следующая попытка» сохраняет сопряжение и настройки.

В звуковых режимах время отсчитывается с сигнала и включает реакцию. «На старт · Внимание · Марш» даёт два разных тона и случайный интервал до финального сигнала. «3 · 2 · 1 · Марш» даёт предсказуемую последовательность. В режиме «Отпустить палец» подготовь попытку и удерживай площадку на стартовом телефоне. Отсчёт начинается с отпускания, по метке сенсорного события браузера. В режиме «Внешний звук» разреши микрофон и дождись сообщения «Ожидаем внешний звук». Резкий хлопок рядом с телефоном запускает отсчёт. Для этого режима нужна тихая зона старта и отдельная проверка задержки микрофона. Створ рассчитан на одного человека в зоне финиша.

## Задачи пилота

- Приёмка на двух iPhone. Сначала 10 контрольных пересечений, где оба телефона стоят рядом и внешний ориентир записывает сигнал и линию на общей шкале. Затем на 60 и 100 м сравнить общий Wi‑Fi и мобильную связь, обменявшись ролями телефонов.
- Предварительные критерии для тренировки: 19/20 валидных пересечений без пропусков, ноль ложных остановок в пустой дорожке, p95 ошибки времени ≤20 мс на откалиброванной паре. Измерять отдельно p95 времени до появления результата, цель ≤1 с при стабильной связи. Для надёжного p95 по каждой ключевой конфигурации собрать минимум 40 контрольных повторов.
- Если Safari выдаёт метку показа кадра или не умеет привязать аудиовыход к монотонным часам, интерфейс маркирует результат как оценку. Для претензии на ±20 мс нужна калибровка даже при наличии обеих меток.
- Прототип охватывает два стартовых звуковых режима, пуск отпусканием пальца и внешним звуком, имя спортсмена и историю. В режиме «С ходу» поставь камеру на каждой линии, проверь оба пересечения и дай себе время отойти для разбега. После паузы стартовый телефон ждёт проход. Считается время от пересечения стартовой линии туловищем до пересечения финишной. Два контрольных кадра остаются на каждом телефоне у его линии. Для серии открой «Серия попыток», введи список имён и число кругов. Пустой список использует имя из поля спортсмена для всех повторов. Успешный замер переводит очередь на следующий номер. По нажатию «Следующая попытка» стартовый телефон может объявить следующего участника, если в браузере установлен голос. CSV содержит ID серии, номер и число попыток. Промежуточные засечки пока не реализованы.

`npm --prefix sprint-timer test` проверяет интерполяцию, порядок событий и восстановление связи. `node sprint-timer/benchmark-network.mjs` воспроизводит тест с заданной задержкой. Данные и разбор в [отчёте](research.md).

Для замеров выгрузи CSV с обоих телефонов. `startRttMs` и `finishRttMs` — выбранный RTT до сервера. `finishToServerMs` — время от метки финиша до получения события сервером, включая обработку видео. `resultArrivalMs` — время от метки финиша до получения результата конкретным браузером перед обновлением экрана. При восстановлении результата из комнаты последняя метрика остаётся пустой. В режиме «С ходу» CSV также содержит источник метки и интервал кадров камеры старта. Влияние погрешности синхронизации сохраняется в этих оценках. Если браузер использует метку показа кадра, часть задержки камеры остаётся за пределами оценки.

### Сверка с контрольной записью

Сохрани отдельные CSV из браузеров старта и финиша. В контрольной таблице с заголовком `id,distance,network,referenceMs` укажи по строке на каждую попытку. Сопоставь успешные замеры с ID из выгрузки и запиши контрольное время в миллисекундах. Для реального прохода, который приложение пропустило, оставь ID пустым и укажи контрольное время. Для прогона без бегуна оставь контрольное время пустым. Если в таком прогоне произошла ложная остановка, укажи её ID из выгрузки. Используй заранее выбранные метки сети, например `wifi` и `mobile`. Добавь колонку `configuration`, если меняешь режим старта, браузер или распределение телефонов по ролям.

```bash
python3 sprint-timer/analyze-pilot.py start.csv finish.csv reference.csv
```

Отчёт выводит число ожидаемых, пойманных, пропущенных и ложных засечек по дистанции и сети. Ошибка рассчитывается по совпавшим парам с контрольной меткой. Для каждой пары указывается источник и размер выборки через число сравнений и число меток поступления. Положительное смещение означает, что Створ показал большее время, чем контрольная запись. p95 на малой выборке годится для первого прогона. Для вывода о точности собери не меньше 40 повторов на конфигурацию.

### Метка по звуку и кадрам одной записи

Для короткой стендовой проверки поставь стартовый динамик рядом с третьей камерой. Камера должна видеть финишную черту и записывать звук. Найди номера соседних кадров перед пересечением и после него, начиная отсчёт с нуля. Передай примерное окно заключительного сигнала в секундах от первого кадра.

```bash
python3 sprint-timer/measure-reference.py control.mov --start-window 4.6 5.4 --finish-frames 1500 1501
```

Команда ищет тон 970 Гц, использует метки дорожек оригинала и выдаёт интервал между двумя кадрами и его середину для `referenceMs`. Точность контрольного видео зависит от синхронизации звука и изображения в самой камере. Не используй звук старта, долетевший до камеры с 60 или 100 м, как метку его возникновения.
