Видео старта и ускорения

Найди корень по .agents/skills/athletics-assistant/SKILL.md. Прочитай docs/video-protocol.md, docs/start-analysis-pipeline.md и относящиеся к человеку прошлые разборы. Сначала посмотри движение; название файла, сообщение о намерении выполнить упражнение и результат распознавания не доказывают фактическое упражнение.

  1. Получи только переданную папку или файлы. Составь реестр с Drive ID, именем, доступностью, полнотой просмотра и человеком. Одинаковые имя и размер — кандидаты на дубли; без полной контрольной суммы тождество не доказано.
  2. Предпочитай ограниченное чтение HTTP Range с сохранением выбранных кадров. Это получение части байтов по сети, а не «просмотр вообще без скачивания». Не сохраняй полный оригинал без необходимости; отсутствие доступных диапазонов не обходи незаметной полной загрузкой.
  3. Сделай обзор, затем непрерывную плотную последовательность каждой выбранной попытки. По редким обзорным кадрам нельзя установить контакты или Wall Single Switch. Запиши интервал и то, что осталось вне просмотра.
  4. Разделяй переднюю/заднюю ногу старта, опорную/маховую ногу текущего кадра, анатомическую сторону и метку модели. Проверь одежду, перекрытия и суставы вручную. Не отражай эталон ради меньшей численной разницы.
  5. Считай контакт №1 первой новой постановкой стопы после выхода; прежнюю опору назови отдельно. Для каждого из первых 3–5 контактов проверь подход к земле, начальную опору и отрыв. Не определяй окончание толчка одним кадром.
  6. Накладывай линии обычным редактором на копию точного кадра. Сохрани координаты, способ выбора точек, SHA-256 кадра и определения углов. Закрытую точку не достраивай. Угол на плоском изображении — проекция, не точный трёхмерный угол.
  7. При непроверенной скорости экспорта не вычисляй реальные частоту, скорость и время опоры. Без масштаба в плоскости дорожки не назначай сантиметры шагов. Таз — ориентир движения, не измеренный центр массы всего тела; положение стопы впереди таза само по себе не доказывает торможение.
  8. Выдай структуру 14 пунктов из templates/start-review.md, но не выдумывай три ошибки, если подтверждена одна. Подробности измерений оставь приложению; основной текст использует «исходная поза», «первый контакт», «третья опора». Время показывай 1:25, при нужде 1:25,3; сырые PTS храни в manifest.

Углы сравнивай только при совпадении фазы, определения, упражнения и допустимого ракурса. Диапазон описаний элиты не является нормой для Wall March. Главный результат — устойчивая механика и сопоставимые 5/10/20/30 м, а не совпадение палочек. Дай каждому 1–3 команды всего, одну основную на повторение, с ощущением и способом проверить перенос.

Сначала сохрани фактические сведения занятия с неизвестными объёмами, затем отдельный пробный план. Оригиналы и служебные manifest остаются в игнорируемой media/. По явному запросу пользователя выбранные собственные производные для телефона хранятся в reviews/assets/ и отправляются в существующий закрытый GitHub. К каждому основному совету показать свой кадр и целевое действие, различая референс и условную схему; обеспечить вертикальное чтение и обычную HTTPS-ссылку. HTML с встроенными кадрами тоже содержит личные данные; публичный доступ не менять автоматически.

Позднейшее сообщение пользователя «В паблик все лей» разрешает текущую открытую публикацию в Ramchike/athletics-reviews с GitHub Pages. Использовать это разрешение, не спрашивать повторно для согласованной публикации. Чужие оригинальные видео не копировать вместе с собственными материалами.
